AUTOMATED MAINTENANCE
- The Static GTFS integrity and deploy gate has a daily scheduled entry point. It runs the actual database verification only when at least 48 hours have elapsed since the last successful verification.
- A skipped daily gate does not update the successful-verification marker.
- Manual workflow dispatch from main runs immediately.
- Pushes to main do not trigger this workflow.
- The ensureDtcStaticData function verifies the pinned archive hash, static route/stop/link data, and fingerprints of the actual Neon rows.
- If Neon already matches the archive, the importer exits without changing data.
- If data is missing or differs, it validates the source, snapshots the current static tables, imports in one transaction, and verifies persisted row fingerprints before commit.
- Failed validation or post-import checks roll back the transaction and fail the workflow.
- Render auto-deploy must remain disabled. The workflow triggers the Render deploy hook after a manual run, or after a scheduled run that repaired data.
- The separate CI workflow is manual-only.

SOURCE ARCHIVE CHECKS
The reviewed DTC archive contains 2,554 routes, 6,812 stops, 65,322 trips and 2,385,381 stop-time rows. A historical sample matched 947 of 996 distinct realtime route IDs (95.08%). This is not a guarantee of current live-route coverage.
The importer checks the feed calendar and refuses expired or invalid calendar data by default. It warns below 98% route-ID coverage and refuses replacement below 90%.

OPERATIONS
- Do not use Render Shell; the free Render compute plan does not include it.
- Do not use the retired browser upload page or old temporary upload-token settings.
- Keep the reviewed DTC ZIP at the exact repository path above.
- To run a manual verification/import, open GitHub Actions, select "Static GTFS integrity and deploy gate", choose "Run workflow", select main, and start it.
- A normal push to main does not run the static-data workflow. For backend changes, run the static-data workflow manually when a backend deployment is required.
- Render auto-deploy must remain disabled so deployment cannot race ahead of database verification.
- Never put DATABASE_URL or deploy-hook URLs in the repository or chat. Store them only in GitHub Actions secrets.
- Review failed workflow logs before changing validation thresholds.
