GTFS NETWORK DATA

Static DTC bus data is maintained from the reviewed ZIP committed at:
server/data/delhi_buses_static_gtfs_v1.zip

Automated maintenance
- GitHub Actions runs on every push to main and every six hours.
- The ensureDtcStaticData function validates the archive, computes its SHA-256, checks route/stop/link counts and fingerprints the actual Neon rows.
- If the database is already an exact match, it exits without writing data.
- If data is missing or differs, it validates the source first, snapshots the old static tables, replaces the data in one transaction, then verifies every persisted row fingerprint before commit.
- If validation or post-import verification fails, the transaction rolls back and the GitHub workflow fails.
- On a main push, Render is deployed only after the database check/import succeeds. On scheduled runs, Render is redeployed only if data had to be repaired.
- Render auto-deploy must remain disabled. Do not manually deploy code changes that have not passed the static-data workflow.

Required GitHub Actions secrets
- NEON_DATABASE_URL: the Neon connection string for the production database.
- RENDER_DEPLOY_HOOK_URL: a Render deploy hook URL for united-delhi-api, configured for the main branch.

Required repository file
- server/data/delhi_buses_static_gtfs_v1.zip

Source archive checks
The reviewed DTC archive contains 2,554 routes, 6,812 stops, 65,322 trips and 2,385,381 stop-time rows. In the previously measured realtime sample it matched 947 of 996 live route IDs (95.08%). The importer warns below 98% and refuses replacement below 90%.
The importer checks the feed calendar and refuses expired or invalid calendar data by default.

Operations
- Do not use Render Shell; the free Render compute plan does not include it.
- Do not put DATABASE_URL or deploy-hook URLs in the repository or in chat. Store them only in GitHub Actions secrets.
- Keep the DTC ZIP at the exact path above. Updating it in main triggers a validated import before the Render deployment.
- Keep Render auto-deploy disabled so a Render deployment cannot race ahead of the database update.
- Review failed GitHub Actions logs before changing any safety thresholds.
