GTFS NETWORK DATA

The website and Android app read static transit data from Neon. Static GTFS is loaded only by an operator-run command from the Render Shell. The backend has no browser uploader or public admin loading endpoint.

DTC bus network
1. Place the reviewed archive temporarily at server/data/delhi_buses_static_gtfs_v1.zip.
2. Deploy the main branch to Render.
3. Open the Render Shell for united-delhi-api and run the loader from the service's server directory:

   DTC_STATIC_FILE=./data/delhi_buses_static_gtfs_v1.zip DTC_STATIC_ALLOW_REPLACEMENT=true npm run import:dtc

The loader validates required GTFS files, route and stop references, public labels, route-stop links and recent live-route ID coverage. It creates hash-named snapshots before replacing the live tables. Replacement and metadata updates commit in one transaction; a failed import rolls back.

The reviewed DTC archive contains 2,554 routes, 6,812 stops, 65,322 trips and 2,385,381 stop-time rows. It matches 947 of 996 distinct live route IDs (95.08%) in the measured sample; 49 remain unmatched. The loader warns below 98% and refuses below 90%.

Metro topology
The supplied Metro archive has 36 directional routes and 262 stops. Its calendar ended on 31 December 2025. Do not use it as a current timetable. To load topology only:

   METRO_STATIC_FILE=./data/dmrc_static_gtfs_v1.zip METRO_STATIC_ALLOW_REPLACEMENT=true METRO_ALLOW_EXPIRED_CALENDAR=true npm run sync:metro

Metro journey durations remain estimates. A current official schedule is needed before timetable-based claims can be made.

After loading
- Verify static_feed_meta and metro_feed_meta counts and source hashes.
- Check /api/search, /api/routes/:id, /api/metro, /api/metro/routes/:id and /api/plan/multimodal.
- Remove the temporary ZIP files from the repository and deploy the clean tree. No GTFS archive should remain in the production source tree.
