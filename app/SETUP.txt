UNITED DELHI — DEVELOPMENT AND DEPLOYMENT

Current production
- Website: https://united-delhi.vercel.app (Vercel, root directory web/)
- API: https://united-delhi-api.onrender.com (Render, root directory server/)
- PostgreSQL: Neon, database neondb
- GitHub branch: main only
- GitHub Actions is manual-only. Routine deploys use Render and Vercel integrations.

Static transit network
- Android and web both read the same routes, stops and Metro network from Neon; no static GTFS copy is bundled into either client.
- Upload the supplied bus and Metro GTFS ZIPs once at https://united-delhi.vercel.app/static-import.html.
- The backend validates the ZIPs and imports them transactionally. Before replacement, it creates hash-named backup tables for the current routes, stops, route-stop links and metadata. Failed imports roll back.
- Bus routes and stops come from the uploaded bus archive. Metro directions and stations come from the uploaded Metro archive.
- The supplied Metro calendar ends 31 December 2025. The file is used for network topology only; Metro timetable claims are not made and trip durations remain estimates.
- Once imported, Neon is the static source for both Android and website. Automatic external static feed refresh remains disabled.

Live vehicle feed
- Delhi OTD GTFS-Realtime is used for live vehicle positions.
- OTD access requires an authorised private key. The backend reads OTD_API_KEY and sends it only to the official endpoint as its documented key query parameter. Keep it in Render secrets only.

Android app
  cd app
  npm ci
  npm run typecheck
  npm test
  npx expo start

Local Windows APK
  npm run build:apk
Requirements: Node 22, JDK 17, Android SDK/platform-tools and PowerShell. Prefer local APK builds; no EAS or GitHub Actions build is required.

Website
  cd web
  npm ci
  npm run dev
Vite, Vercel and Android configurations use https://united-delhi-api.onrender.com.

Vercel settings
- Root Directory: web
- Framework: Vite
- Install Command: npm ci
- Build Command: npm run build
- Output Directory: dist

Backend
  cd server
  npm ci
  npm run check
  npm test
  npm start

Render environment
- DATABASE_URL
- OTD_API_KEY (authorised OTD realtime access; backend only)
- STATIC_IMPORT_TOKEN (temporary; clear after both ZIPs are imported)
- APP_ORIGINS=https://united-delhi.vercel.app
- DTC_STATIC_AUTO_IMPORT=false
- METRO_AUTO_SYNC=false
- METRO_ALLOW_EXPIRED_CALENDAR=true permits Metro topology-only use; it does not validate timetable dates.

Security
Never commit DATABASE_URL, OTD_API_KEY or STATIC_IMPORT_TOKEN. The upload token is accepted only in the x-static-import-token header over HTTPS and is never stored in the client browser. Clear it from Render after both imports finish.
